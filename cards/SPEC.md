# Decision Card 规范 v0.1（决策卡）

> 一张决策卡 = 一个场景的完整判断定义：问题 + 选项 + 评分标准。
> 给 laya 递一张新卡，它就多会一个场景——**新场景 ≠ 重新训练**。
>
> 设计对标 Anthropic 的 SKILL.md：一个 md 文件，frontmatter 元数据 + 结构化正文，
> 人可读可写可版本管理，机器一行加载。

## 文件规范

- 文件名：`<卡名>.card.md`（卡名建议全小写连字符，如 `life-admin.card.md`）
- 编码 UTF-8
- 结构 = YAML frontmatter（元数据）+ `## Questions` 正文（问题定义）+ 任意附注（给人看，不进推理）

## 完整示例

```markdown
---
card: life-admin
version: 1
description: 生活管家场景：日程/购物/健康/出行/家务路由 + 打扰判断
author: Fuyao
---

（本节起：任意人类阅读内容——场景说明、示例、变更记录。**不进推理**。）

## Questions

### route （choice）
这条生活消息该交给哪个管家技能？

- schedule: 日程安排：约会、会议、提醒
- shopping: 购物消费：想买、下单、退换
- health: 健康：就医、用药、锻炼
- travel: 出行：通勤、订票、路线
- home: 家务：保洁、维修、缴费
- chat: 纯闲聊，不用执行

### interrupt （noul）
这条消息是否需要立刻去办？
```

## 字段定义

### frontmatter（必填三件）

| 字段 | 类型 | 说明 |
|---|---|---|
| `card` | str | 卡名，与文件名一致 |
| `version` | int | 卡版本，格式变更时 +1 |
| `description` | str | 一句话场景说明 |

### Questions 正文

每个问题一节：`### <问题ID> （<类型>）`

| 类型 | 紧跟内容 | 列表含义 | 输出 |
|---|---|---|---|
| `choice` | 问题句（instructions） | `- 标签: 描述`（≥2 项） | Top 标签 + 概率分布 + 置信度 |
| `noul` | 问题句 | 可省略；需要时 `- 描述: 反面描述`？否——noul 列表仅在有自定义 false/true 描述时用：`- true: 要求加快速度` 换行 `- false: 不要求` | P(true) ∈ [0,1] |
| `score` | 问题句 | `- 档1` / `- 档2` …（**有序**，从低到高） | 期望档位 + 分布 |

## 硬预算（超出 = 校验失败，不会静默丢）

- 前缀（instructions + 全部候选项）≤ **256 token**（v5b 配置；v0.1 配置为 192）。中文实测 ≈0.68 token/字 →
  6 选项时每条描述 ≤30 字；3 选项 ≤60 字；2 选项 ≤85 字
- 全序列 ≤ 1024 token（state 用户话语约留 250–300 汉字）
- 校验：`laya --lint 卡文件`（本地试算 token，精确到每问）

## 写卡手艺（准确率的 80% 在这里）

1. **描述写"判断依据"，不写同义改写**——"需要立刻处理的生产事故：宕机、数据丢失" ✓；"紧急的事" ✗（模型学不到边界）
2. **标签语义边界拉开**——两个选项描述有重叠时，重叠区样本必摇摆；实在要分，加"区别于 X"句式
3. **每条描述带 2-3 个典型例举**（顿号列举），例举比抽象词更能锚定语义
4. **加一个"兜底标签"**（none/chat/other）承接不属于任何选项的输入，并写清"不满足以上任何" 
5. **问题句用中文直接问**，别绕（"这条消息该交给哪个技能？" ✓）
6. **卡要小**：一个场景一张卡，别把全公司流程塞一张卡——选项越多每条描述越短，判断越糊
7. 卡写完先跑 `laya --lint`，再拿 5-10 条真实样本试打分，错例回来改描述（改描述 ≠ 改模型，成本毫秒级）

## 与模型配合（运行时协议）

```bash
laya --card cards/life-admin.card.md "下周三帮我约个牙医"        # 单次判断
laya --lint cards/life-admin.card.md                            # 只校验
laya --cards cards/                                             # 列出目录下所有可用卡
```

服务模式（常驻进程，body 直接传 questions，等价于卡片内容）：

```bash
curl -X POST 127.0.0.1:18766/predict -d '{"state": "...", "queries": {...}}'
```

置信度门控（可选）：choice 置信 < 0.6 或 noul ∈ [0.4, 0.6] 时升级给大模型复判——
laya 管快思考，拿不准的上交（System One / System Two 分层）。

## 设计决策记录（为什么是现在这个样子）

- **md 而非 json**：卡的作者是"想给小模型加场景的人"（含非程序员）；md 可注释可长写、
  git diff 友好、与 SKILL.md 心智一致。机器消费由解析器承担（内置，零额外依赖）
- **version 整数递增**：规范演化留口（v0.1 只含三类原语；未来新原语向后兼容追加）
- **附注区不进推理**：保证"写什么进模型"完全可预测——进考卷的只有 Questions 区
- **lint 内置而非事后**：预算超限是新手必然踩的坑，报错信息直接指出"哪一问、超多少 token"
